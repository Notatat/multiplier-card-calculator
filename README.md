# 倍卡路线计算器

浏览器端静态工具，支持动态持卡列表、三种替换方案，以及路线最大操作天数限制。依据现有规则及生成式AI编辑生成，仅供参考，请仔细校对。

## 使用

需要 Node.js 运行测试，Python 3 启动本地预览。无第三方运行依赖，无需安装依赖包。

```sh
npm test
npm run check
npm start
```

浏览器打开 `http://127.0.0.1:8080`。也可以把五个页面文件部署到静态托管服务，保持相对路径即可。累计访问次数需要额外运行下方的轻量计数服务；纯静态预览时显示“暂不可用”，不影响计算。

## 输入与方案

- 初始时长输入到分钟，倍率支持1.1、1.2、1.3、1.5、2。
- 持卡按行追加：5分钟、1天、7天、14天 × 五种倍率，共19种有效组合，2倍卡最长7天，不允许14天2倍卡；相同组合自动合并，每种最多9999张。
- 仅最后一张2倍：最多使用一张2倍卡，并用于最后一步。
- 每天2倍收尾：每天最多一张2倍卡收尾；库存不足时优先最后一天及靠后日期，不为使用2倍卡额外拆天。
- 最长时长：允许在合法顺序中使用多张2倍卡，以最终时长最大为目标。
- 仅使用天卡：排除所有5分钟卡，保留原库存数据。
- 高级设置：默认折叠，可设置五种倍率的接替前限制和2倍终点上限，支持0.01～99999天及最多两位小数。留空使用默认值。五项接替前限制检查使用下一张卡前的当前时长；最后一步可超过接替前限制并停止。2倍终点上限限制最终结果。
- 路线最多天数：留空不限，设置后只返回能在该操作天数内完成的路线。此项不限制最终倍卡时长。三个方案均适用，搜索中断时返回的可行路线也必须满足上限。

## 计算规则

1. 每天最多替换10次，可跨天；N次操作使用向上取整的N/10天。每天收尾方案允许提前结束某一天。
2. 当前倍率时长超过45天，不能再使用同倍率卡。不同倍率可转换，但仍须满足当前倍率的接替前限制。
3. 2倍时长超过接替前限制后不可再使用任何卡片，默认45天，可在高级设置修改；跨天不解除锁定。等于限制可继续，初始状态也适用。
4. 使用每张卡前，当前倍率时长须满足：2倍≤45天、1.5倍≤162天、1.3倍≤263天、1.2倍≤390天、1.1倍≤770天。等于限制可继续，超过后不能再使用任何卡片；终点可以超过接替前限制。初始状态也适用；若已为目标倍率，可保留原状态。五种倍率接替前限制均可在高级设置修改。2倍终点另外限制为88天，可自定义，没有最低77天要求。单张2倍卡最长7天。
5. 有2倍卡时求当前方案下的最长2倍结果，没有最低天数要求；没有2倍卡时求最长1.5倍结果。初始2倍已锁定时只能保留该状态。
6. 新时长＝原时长×（原倍率−1）÷（新倍率−1）＋卡片时长。
7. 优先最长时长，同分优先更多1.5倍卡累计收益，再选更少步骤。每天收尾方案同分时优先靠后日期收尾。
8. 分天仅安排操作次数与收尾，不扣除现实等待时间的自然消耗。结果及每一步精确到秒。

最多约25秒或100万搜索状态。完整搜索后才标记最优；中断会明确说明尚未证明最优，暂未找到结果不代表无解。

## 核心接口

```js
const { solve } = require('./solver.js');
const result = solve({
  minutes: 0,
  rate: 5, // 10 × (倍率 - 1)：1、2、3、5、10
  cards: [
    { minutes: 1440, rate: 5 },
    { minutes: 1440, rate: 10 }
  ],
  counts: [2, 1],
  mode: 'final-double', // 另有 daily-double、longest
  dayCardsOnly: false,
  maxRouteDays: 1, // null 或省略为不限
  limits: { rate11Days: 770, rate12Days: 390, rate13Days: 263, rate15Days: 162, doubleBeforeDays: 45, doubleEndDays: 88 } // 可省略，使用默认值
});
console.log(result.days, result.route);
```

`solver.js`独立支持Node.js和Web Worker。`inventory.js`负责库存合并及历史存储格式迁移，`app.js`负责页面交互。测试使用合成数据与独立穷举对照，覆盖接替前边界、超限终态、自定义值、三种方案、跨日与库存筛选。

## 隐私

输入只存储在当前浏览器localStorage，计算在本地Web Worker中完成，不上传输入。页面每次打开或刷新只向计数接口发送一次空POST；累计访问次数不去重。计数服务仅保存一个整数，不保存IP、UA、Cookie或计算输入。仓库不包含服务器地址、部署凭据、访问日志、浏览器数据或个人资料。页面的GitHub和原帖链接是普通外链，点击后会离开本站。

## 页面互动与计数

群友致谢会轻微扭动，并在鼠标靠近或点击时在独立区域内避开；触屏及系统减少动态效果模式保持静止。页面计数展示为“累计帮助了 X 名小伙伴”，沿用简单页面浏览计数。

标准库Python服务，SQLite持久化，无需第三方依赖：

```sh
python3 -B server/visit-counter.py --database /path/to/visits.sqlite3 --port 8766
```

固定监听127.0.0.1；GET `/visit`只读，POST `/visit`加一，返回`{"visits": 数字}`。部署时将页面相对地址`api/visits`反代至该接口，并关闭此接口的访问日志。数据库应放在网站公开目录以外，更新源码不应覆盖数据库。单独运行测试：`python3 -B tests/visit-counter.test.py`。
